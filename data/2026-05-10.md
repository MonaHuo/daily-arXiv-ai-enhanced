### [1] [Anatomy of a Query: W5H Dimensions and FAR Patterns for Text-to-SQL Evaluation](https://arxiv.org/abs/2605.05525)
*Vicki Stover Hertzberg,Eduardo Valverde,Joyce C. Ho*

Main category: cs.DB

TL;DR: 本文提出了QUEST框架，通过结构化的FAR模型和语义维度的W5H模型分析查询。研究发现，虽然查询结构具有通用性，但现有问答系统在深度因果与过程推理方面存在严重短板。


<details>
  <summary>Details</summary>
Motivation: 自然语言数据库接口日益流行，但目前缺乏评估与设计此类系统的统一理论基础。

Method: 提出了QUEST（查询理解评估通过语义翻译）框架，包含两个核心部分：1. FAR结构不变式：认为所有合规查询均可归约为过滤（Filter）、聚合（Aggregate）和返回（Return）操作；2. W5H维度框架：将过滤标准归类为六个语义维度（Who, What, Where, When, Why, How）。

Result: 通过在五个Text-to-SQL数据集（120,464个样本）上验证，发现FAR结构在所有领域均适用；而W5H维度特征在不同领域差异巨大，尤其在医疗领域中时间（WHEN，80.4%）和人员（WHO，73.0%）维度占比极高，且在所有领域中因果（WHY）和过程（HOW）推理几乎缺失。

Conclusion: 目前文本到SQL（Text-to-SQL）系统在因果推理（WHY）和过程推理（HOW）方面存在显著空白，这些领域是实现结构化数据真实机器推理的必经之路。

Abstract: Natural language interfaces to databases have gained popularity, yet the theoretical foundations for evaluating and designing these systems remain underdeveloped. We present QUEST (Query Understanding Evaluation through Semantic Translation), a framework resting on two independently motivated components: the FAR structural invariant, which holds that every well-formed query reduces to Filter, Aggregate, and Return operations; and the W5H dimensional framework, which holds that all filtering criteria map to six semantic dimensions (Who, What, Where, When, Why, and How). Validated across five text-to-SQL datasets (n = 120,464), FAR conformance is universal across all domains and schema types, while W5H dimensional profiles vary substantially. Healthcare queries are strongly concentrated in temporal (WHEN: 80.4%) and person-centric (WHO: 73.0%) dimensions far exceeding general-domain benchmarks, and causal (WHY) and mechanistic (HOW) reasoning are near-zero everywhere, with apparent HOW exceptions reflecting quantitative aggregation rather than genuine procedural reasoning. These results identify a frontier that must be crossed for genuine machine reasoning over structured data.

### [2] [An Extensible and Verifiable Language for Query Rewrite Rules](https://arxiv.org/abs/2605.05536)
*Sicheng Pan,Shuxian Wang,Wesley Zheng,Zirong Zeng,Vijay Sharma,Alvin Cheung*

Main category: cs.DB

TL;DR: 本文提出了 Rulescript，一种用于数据库查询重写的通用 DSL，通过将规则定义与执行引擎解耦并实现形式化验证，实现了跨不同数据库引擎的重写规则复用。


<details>
  <summary>Details</summary>
Motivation: 现有数据库查询重写规则多为手动实现，与特定执行引擎高度耦合，开发工作量大，缺乏可移植性，且容易引入逻辑错误。

Method: 引入 Rulescript，一种与引擎无关的 DSL。通过基于关系代数的核心语言将规则分解为“匹配”和“转换”两个阶段，并引入自动形式化验证机制。通过轻量级适配器映射到不同数据库引擎（如 CockroachDB 和 Apache Data Fusion）。

Result: 成功复现了 Apache Calcite 的 33 条重写规则，并将其自动部署到架构差异巨大的 CockroachDB 和 Apache Data Fusion 中，验证了该方案的高效性和高度的可移植性。

Conclusion: Rulescript 实现了查询重写规则的“一次编写，到处运行”，证明了通过领域特定语言（DSL）来解耦规则定义与执行引擎，能够有效降低开发成本、提高可移植性，并保证规则的正确性。

Abstract: Logical query plan rewriting transforms a relational database query into an equivalent but more efficient form and is crucial to the performance of database-backed applications. In existing systems, rewrite rules are typically implemented manually, tightly coupled to specific execution engines, and often lack formal correctness guarantees. Consequently, developing a new engine requires reimplementing both legacy and new rules, incurring significant engineering cost, limiting portability, and every new implementation is an opportunity for introducing new bugs.
  We introduce Rulescript, an engine-agnostic domain-specific language (DSL) for developing query rewrite rules. Rulescript separates rule definition from execution infrastructure via a relational algebra-inspired core language and an explicit decomposition of rules into matching and transformation phases. Developers express rewrites by pattern-matching query plans using Rulescript's core operators and constructing semantically equivalent transformed plans, with all rewrites automatically verified formally to ensure correctness. Rulescript is extensible: users can define custom operators in terms of the core language to capture engine-specific semantics. To integrate with an existing system, developers need only implement a lightweight adapter that maps Rulescript's core and custom operators to the operators implemented in the target engine.
  We evaluate Rulescript by reimplementing 33 rewrite rules from Apache Calcite and extending the language with several custom operators. To demonstrate portability, we automatically deploy these rules to CockroachDB and Apache Data Fusion, two engines with substantially different backends. Our results show that Rulescript enables "write once, deploy everywhere" paradigm for query plan rewriting, with minimal effort required to deploy previously written rules on a new data engine.

### [3] [Low-Latency Out-of-Core ANN Search in High-Dimensional Space](https://arxiv.org/abs/2605.05787)
*Ziwen Song,Bin Wang,Xiaochun Yang,Junhua Zhang*

Main category: cs.DB

TL;DR: 本文提出了 SkipDisk，一种磁盘-内存混合的 ANN 搜索方案。通过更紧密的下界过滤、高效的数据剪枝和异步 I/O 设计，SkipDisk 在显著降低内存占用（至原先的 10%-20%）的同时，实现了比 HNSW 更低的搜索延迟。


<details>
  <summary>Details</summary>
Motivation: 现有的内存图结构 ANN 搜索内存成本过高，而磁盘基方法又受限于磁盘的高访问延迟。如何在大规模内存限制下保持低延迟搜索是当前的主要挑战。

Method: 1. 改进过滤：为每个点设计专用枢纽（pivot），利用三角不等式构建更紧密的搜索下界以减少磁盘 I/O；
2. 数据剪枝：采用三级数据剪枝策略，将高信息量数据保留在内存中以压缩内存占用；
3. 异步 I/O：通过将邻居节点保留在内存中，实现内存搜索与磁盘访问的解耦，并引入异步 I/O 策略提升整体访问效率。

Result: 在保持约 10% 内存使用率的情况下，延迟为 HNSW 的 85%；在保持约 20% 内存使用率的情况下，延迟进一步降低至 HNSW 的 63%。

Conclusion: SkipDisk 通过更紧密的下界过滤、三级数据剪枝策略以及异步 I/O 机制，成功在显著降低内存占用的同时，实现了优于传统内存索引（HNSW）的搜索延迟，验证了磁盘-内存混合 ANN 搜索的可行性与高效性。

Abstract: In-memory graph-based approximate nearest neighbor (ANN) search has superior search performance but incurs significant memory footprint. Disk-based methods reduce memory usage but suffer from high disk access latency. A common challenge is how to achieve low-latency search while significantly reducing memory footprint. In this paper, we propose SkipDisk, a disk-memory hybrid ANN search that significantly reduces memory footprint while achieving search latency comparable to or lower than in-memory method HNSW. By analyzing existing disk-based methods, we observed that disk access remains the primary bottleneck, and existing lower bound based filtering methods are two loose to effectively reduce disk access. Therefore, we design SkipDisk to achieve tight lower bound with low memory footprint to reduce the search latency. First, we design a dedicated pivot for each point to improve the lower bound of the triangle inequality for effective filtering. We further design an estimation-based approach based on this lower bound. Second, to reduce the memory footprint, we employ a three-level data pruning strategy to preserve informative data in memory. Third, to further reduce search latency, we design an asynchronous I/O strategy based on the decoupling of in-memory search and disk access by storing neighbor nodes in memory. Experiments show that our method achieves a latency of 85 of HNSW's latency with approximately 10 memory footprint, and a latency to 63 of HNSW's with a slightly higher memory footprint of around 20.

</details>
